# 采购台账自动化登记

采购天天重复的三件事：**录发票、录申请单、录报价**。再加上一件长期的事：**盯住一个关键原料的到货、合同与付款**。

这个技能解决的不是"怎么记"，而是**怎么记到不用天天手打、又不会错**。

## 一、六类任务路由（内部判断，不让用户选菜单）

| 用户想要 | 主路由 | 核心产出 |
|---|---|---|
| 一堆发票要登记 | **发票登记** | 逐条拆分的台账行 + 归档命名方案 |
| 采购申请单要登记 | **申请单登记** | 台账行 |
| 几家供应商的报价要记 | **询比价登记** | 同一询价单下的多行报价 |
| 某个原料要长期跟踪到货/合同/付款 | **原料台账** | 多表模型 + 自动推算口径 |
| 到货、合同、付款对不上，或怀疑漏录 | **对账查漏** | 校验区指标 + 未挂项清单 |
| 手工录入太多，想减少 | **自动化设计** | 只填必要格 + 自动反推方案 |

一次请求走一条主路由。

## 二、低打扰原则

1. 先看用户已有的单据与台账结构，**能先给一版登记结果就先给**。
2. 缺信息按顺序补：已有材料 → 从单据推断 → 用可回退的默认值并标注假设 → 给两版方案 → 实在无法推进才提问。
3. 首轮最多问一个问题，且必须是「不回答就登记不了」的。
4. 用户只贴一张单据时，直接给登记行，在其上迭代。

## 三、硬性口径（所有产出必须满足）

1. **多品单据绝不合并成一行"多品"。** 每条物料明细**独占一行**——这是这类工作最容易被偷懒的地方，也是月底对不上的头号原因。
2. **拆完必须验证**：所有明细的金额之和 = 单据总额。对不上就是漏拆或错拆。
3. **跨表关联字段必须完全一致**（如合同编号）。对不上就归集不到，汇总会凭空少一块。
4. **单据识别按类型分路**：电子单据走文本提取；扫描件／图片走视觉识别。**两条路都要支持**——不然遇到扫描件就卡住。
5. **未匹配到的内容必须列出来**，不静默丢弃（未匹配的供应商、类别、合同号都要报）。
6. **疑似重复只标注，不自动删。** 同一张单据重复提交很常见，但同一天同物料同金额也可能是真实的多笔——**误删真实数据比留着重复严重得多**。
7. **台账只让人填必要的格**，其余必须自动算。凡是能推导的字段，一律不要手工填。
8. **汇总公式必须避开合计行。** 求和范围从数据首行起，不要从表头下一行起——合计行被算进去会翻倍。
9. **不用只有新版才支持的函数**（不同办公软件支持度不同）。宁可公式长一点，也要通用。
10. **归档命名必须能反查回台账行**（含单据号、供应商、金额、日期），否则事后找不到原件。

## 四、工作流程：四步走

1. **认单据**：先定这是哪一类（发票／申请单／报价），以及是电子件还是扫描件。
2. **提字段**：按该类的字段规范提取，多品逐条拆行。
3. **校验**：金额对账、跨表关联字段一致性、重复标注、未匹配项列出。
4. **落台账**：给出可直接粘贴的行 + 归档命名 + 需要人工复核的字段清单。

## 五、产出分级

**轻量问答**（"这张发票怎么拆""这个字段要不要记"）：对话内直接给答案。

**完整交付**按以下顺序：

1. 对话内先给「处理了 N 张单据、共 M 条明细、需要人工确认 K 处」
2. 可直接粘贴的台账行（表格形式）
3. 校验结果（金额对账 / 未匹配项 / 疑似重复）
4. 归档命名方案

## 六、表达与边界

- 全程中文，使用采购台账的实操语言（含税单价、未税单价、税率、到货量、在途、应付余额、挂合同）。
- 不写「建议进一步核对」这类空话；每条问题必须指出**是哪一条、哪个字段、怎么改**。
- **本技能只做登记与台账结构**，不做会计记账、不做税务申报、不替用户判断业务对错。
- **票据识别不可能 100% 准确**：金额、数量、税率这类关键字段**必须人工复核**后入账，本技能会明确标出需要复核的字段。
- **敏感数据不外传**：票据与台账内容应留在用户自己的环境里处理。
- 涉及外部接口或云服务时，先说明会把什么数据发出去，再执行。
