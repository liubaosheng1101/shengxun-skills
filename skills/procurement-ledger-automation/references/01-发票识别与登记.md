# 01 · 发票识别与登记

发票是采购登记里**最高频、也最容易错**的一类。错的代价不只是记错一行——它会让月底的金额对不上，而那时已经很难回溯。

## 一、字段规范（每条明细一行）

| 字段 | 说明 | 注意事项 |
|---|---|---|
| 日期 | 开票日期 | 格式统一；注意可能是文本、日期值或序列号（见下） |
| 物料名称 | 发票上的品名 | 原样保留，另起一列做标准化 |
| 规格型号 | 如有 | |
| 单位 | 如有 | |
| 数量 | | |
| 未税单价 / 税率 / 含税单价 | 三者要能互相验证 | 常见只给其中两个，第三个要算出来 |
| 金额 | 该行金额 | **以发票为准**，算出来的值只作校验 |
| 供应商名称 | 销售方 | |
| 联系人 / 电话 | 查通讯录补 | 匹配不到就留空并列出 |

⚠️ **建议保留两列物料名称**：`原始品名`（发票上是啥写啥）+ `标准品名/类别`（标准化后的）。**直接覆盖原值会让原始信息不可回退。**

## 二、识别：按单据类型分两条路

**这是遇到"识别不出来"时的第一个分叉点。**

| 类型 | 做法 | 适用 |
|---|---|---|
| **电子票据**（PDF 由系统生成） | 直接**提取文本**，再用规则匹配 | 文字可选中、可复制 |
| **扫描件 / 照片** | 转成图片后**用视觉识别** | 文字是图像，提不出文本 |

**电子票据的两个技巧**：

1. **销售方在购买方之后**——文本里会出现多个"名称："，**取最后一个**通常是销售方。
2. **明细表格可能被合并成一行文本**——这时要**按坐标（位置）解析**，不能只按行读。

**扫描件的注意点**：

- 先转成图片再识别，**分辨率调高一些**（低了会认错数字）。
- **一张 PDF 里可能有多张发票**——要**逐页处理**，不要只读第一页。

## 三、多品逐条拆分（最容易偷懒的一步）

⛔ **绝不允许把多条物料合并成一行"多品"。**

**每条明细必须独占一行。** 合并的后果：

- 数量、单价、金额全都没法按物料统计
- 按类别汇总时这一行归不进去
- 事后想拆开，得回去翻原始发票

**拆完必须验证**：

```
所有明细的含税金额之和 == 发票含税总额
```

对不上就说明漏拆或错拆，**必须先查清楚再入账**，不要"先记上回头再说"。

## 四、自动匹配（能省掉大量手打）

### 物料名称 → 统一类别

建一张**显式映射表**（关键词 → 类别），**不要靠模糊猜**：

```
<类别A>: [关键词1, 关键词2, 关键词3]
<类别B>: [关键词4, 关键词5]
...
其他: []        # 兜底
```

**未匹配到的品名必须收集并打印出来**——它们是这张表该补的条目。判据是：未匹配计数为 0，或未匹配项已逐条确认。

⚠️ 关键词里要包含**同义写法与常见错别字**（同一物料在不同发票上写法可能不同）。

### 供应商 → 联系人 / 电话

从供应商通讯录匹配。**匹配规则**：双方都去掉企业后缀（"有限公司""公司"等）后比较**包含关系**；匹配不到的在输出里**单独列出**，不要静默留空。

> ⚠️ 供应商名称里可能嵌换行符或多余空格——**比较前先去空白**，否则明明有也匹配不上。

## 五、日期字段：三种形态都要处理

发票日期可能是：**日期值** / **文本**（`2026-07-23`、`2026年7月23日`）/ **单元格序列号（整数）**。

**只判其中一种会静默丢行**，而且不会报错。统一解析函数与判据见台账清洗类文档的同名章节（要点：三种都处理 + 解析失败必须计数并打印原始值）。

## 六、归档命名：必须能反查回台账

处理完的单据要改名归档，**命名里带上台账的关键字段**，否则事后找不到原件。

推荐格式：

```
<单据号>_<供应商简称>_<物料简称>_¥<金额>_<日期>.<扩展名>
```

**规则**：

- 文件名里**不能出现路径分隔符或冒号**，出现就替换掉（否则存盘失败）。
- **多张单据合并在一个文件**时，用另一种格式：`多张单据合集_<N>张_<主要供应商>_¥<总金额>_<日期>`。
- 归档目录**按月分文件夹**，避免单目录文件过多。

## 七、处理完的输出格式

```
## 处理完成

| 序号 | 供应商 | 日期 | 物料 | 金额 |
|---|---|---|---|---|
| ... | ... | ... | ... | ... |

- 共处理 N 张单据，M 条明细
- 台账追加至第 X 行
- ⚠️ 未匹配联系人：[...]
- ⚠️ 未匹配类别：[...]
- ⚠️ 需人工复核字段：金额、数量、税率
```

**"未匹配"与"需复核"必须显式列出**——这是这个流程最有价值的部分，它把"看起来成功了"变成"确实处理干净了"。

## 八、自检

- [ ] 多品已逐条拆行，没有"多品"行
- [ ] 明细金额之和 = 单据总额
- [ ] 每条明细的金额 = 数量 × 含税单价（不一致的已标注）
- [ ] 日期全部解析成功（失败计数为 0 或已逐条确认）
- [ ] 未匹配的类别与供应商已列出
- [ ] 疑似重复已标注（未自动删除）
- [ ] 归档命名含单据号与日期，可反查
- [ ] 关键字段（金额/数量/税率）已提示人工复核
