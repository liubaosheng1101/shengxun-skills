# 03 · 原料采购台账模型（长期采购的关键原料）

适用于：某个原料**常年采购**——一年到头都在买，有多个供应商、多份合同、持续到货、还有预付款要盯。

单月台账记不住这种场景：**它只能告诉你"这个月花了多少"，回答不了"还欠多少货、还差多少没到、钱付到哪一步"**。

## 一、七张表的分工

| # | 表 | 作用 | 谁填 |
|---|---|---|---|
| ① | **看板** | 到货指标 · 提醒横幅 · 按供应商汇总 · 合同执行概览 | 全自动 |
| ② | **到货记录** | ★ 核心录入：一天一行（一个供应商一份合同） | 手填少量 |
| ③ | **合同跟踪** | 每份合同到了多少、还差多少 | 手填少量 |
| ④ | **应付账款** | 欠多少 / 预付了多少、按供应商汇总 | 全自动 |
| ⑤ | **日报** | 每天只填日期 + 库存 + 明日计划，用量自动反推 | 手填 3 格 |
| ⑥ | **付款记录** | 逐笔付款 | 手填 |
| ⑦ | **参数** | 安全库存 / 提前期 / 每车吨数 / 日耗 / 账期 | 手填一次 |

**设计哲学**：把"要人记"的压到最少，把"能算出来"的全部交给公式。**七张表里真正要手填的字段不超过十个。**

## 二、表② 到货记录（最重要）

### 列结构

| 列 | 字段 | 来源 |
|---|---|---|
| A | 日期 | 手填 |
| B | 供应商 | 手填 |
| C | **合同编号 / 现货** | 手填，**必须与合同跟踪的编号列完全一致**；无合同的到货填"现货" |
| D–O | 第1车车号 / 第1车吨数 … 第6车 | 有几车填几车 |
| P | 车数 | 自动（统计各车吨数非空的个数） |
| Q | 当日到货合计 | 自动（各车吨数求和） |
| R | 合同量 | 自动（按合同编号取） |
| S | 合同累计到货 | 自动（按合同编号汇总 Q） |
| T | 未到量 | 自动（R − S） |
| U | 到货状态 | 自动（已到齐 / 在途；现货不参与） |
| V / W | 凭证号 / 备注 | 手填 |

### 录入规则（关键）

- **同一天、同一供应商、同一合同的多车 → 合成一行**，填多个车槽
- **不同供应商或不同合同 → 各占一行**
- 这样"每天各家到了多少车、多少吨"一眼就能看清

### 为什么要"车"这一层

因为大宗原料**按车计量**：合同签的是吨数，实际是几车几车到。**把车号和吨数横排，就等于同时记了"进度"和"明细"**——不用另建一张车次表。

**"现货"要单独标出来**：现货不挂在合同上，如果和合同到货混在一起，合同进度会算错。填了"现货"的行，R/S/T/U 这几列**留空**，不参与合同计算。

## 三、表③ 合同跟踪

**只填七个字段**：合同编号 / 供应商 / 签订日期 / 合同量 / 单价 / 经办人 / 备注。

其余全是自动列：合同金额、已到货量、未到量、到货率、状态、约定车数、实际车数、在途未到量。

### ⚠️ 未到量（在途）的口径必须唯一

这是最容易算出多个不同数字的地方。**口径定为**：只统计"**实际车数 < 约定车数**"的合同。

**为什么**：按车执行的合同常有**自然尾差**（合同签 100 吨、实际 99.5 吨到齐，按吨算会永远差 0.5）。如果不排除，在途量会常年虚挂。

**三条容易踩的坑**：

| 坑 | 后果 |
|---|---|
| 求和范围**包含合计行** | 数字翻倍 |
| 用"状态 ≠ 已结束"来筛 | 合计行被命中 → 虚报 |
| 直接用"未到量"列汇总 | 含自然尾差 → 与在途口径不同值 |

**统一用"在途未到量"这一列做汇总，范围从数据首行起。**

## 四、表④ 应付账款

### 核心等式

```
到货金额 = 已到货吨数 × 单价
预付金额 = 付款记录里挂在这份合同上的已付
应付金额 = 到货金额 − 预付金额
```

**正负号的含义（很重要，且反直觉）**：

| 符号 | 含义 | 该做什么 |
|---|---|---|
| **正数** | 我欠供应商 | 安排付款 |
| **负数** | **我预付多了、供应商欠我货** | **盯发货、催货** |

⚠️ **先款后货的品种，负数才是常态。负得越多，越要盯发货**——很多人的台账只盯"欠钱"，把"欠货"这一侧漏掉了，结果钱付了货没到，账上却看不出异常。

### 状态标记

`未开始 / 待付款 / 待催货 / 超付 / 款货两清`——**"待催货"这一档是上面那条等式带来的**，没有它就会漏掉欠货风险。

## 五、表⑤ 日报：只填三个格

**每天只需要填**：日期 / 当前库存（盘点值）/ 明日计划到货。

**其余全部自动**：

| 列 | 怎么算 |
|---|---|
| 到货车数、到货量 | 从到货记录按日期取 |
| 库存变动 | 当日到货 − 当日用量 |
| **用量** | **上日库存 + 当日到货 − 当日库存**（反推） |
| 可用天数 | 库存 ÷ 参数表里的日耗 |
| 在途未到量 | 从合同跟踪取 |
| 预计断料日 | 日期 + 可用天数 |
| **建议下单日** | **预计断料日 − 提前期** |

### 用量反推公式的要点

反推的公式必须**不依赖行的排序**（升序、降序都能算对）。做法：先找"日期早于本行、且填了库存的最近一行"，取其库存，再代入上式。

**三条避免踩的坑**：

- ⛔ 不要用只有新版才支持的 `MAXIFS`（部分办公软件不认）
- ⛔ 不要用依赖排序的查找写法（换个排序就全错）
- ⛔ 首行或找不到前一日时，**要判空显示空白**，否则会算出"到货 − 库存"这种荒唐值

### 指标锚定：不要钉死行号

看板类指标**不要指向固定的某一行**（如"永远取第 9 行"），要用公式**找"最新那一行"**。

⚠️ 而且要**两套锚**：

- "最新日期 / 到货车数 / 到货量" → 取**最新有日期的行**
- "当前库存 / 可用天数 / 断料日 / 建议下单日" → 取**最新填了库存的行**

**为什么两套**：实际录入经常出现"先记了日期、库存忘填"的行。用"有日期的行"去取库存，会显示空白或 0。

### 提醒横幅

在日报或看板顶部放一条自动生成的提醒，把最要紧的事说出来：

> ⚠️ 建议下单日 **<日期>** 已到/已过 —— 当前库存 X 吨，按日均 Y 吨/天约可用 **Z 天**，请尽快安排下单。

**这一条比任何图表都管用**——它把"要看懂一堆数字才知道该干什么"变成了一句行动指令。

## 六、表⑥ 付款记录

逐笔记录，**必须挂合同编号**（否则预付款归集不到合同上，校验区会报警）。

- 序号**用公式自动生成**，增删行自动重排，不用手改
- 供应商、合同编号、付款方式**挂下拉**，减少手打与抄错

## 七、表⑦ 参数

| 参数 | 用途 |
|---|---|
| 安全库存 | 库存低于它就报警 |
| 安全天数 | 兜底阈值 |
| 提前期 | 算建议下单日 |
| 每车吨数 | 换算车数 |
| 日耗 | 算可用天数 |
| 账期 | 算应付到期 |
| 储罐容量 | 判断能不能囤 |
| 停产/复产 | 异常期调整 |

**参数集中放一处**，公式全部引用它——改一个数，全表跟着变。**不要把参数写死在公式里。**

## 八、建模顺序

1. 先填**参数**（没有它后面的公式没法算）
2. 再建**合同跟踪**（有合同才有后续）
3. 再建**到货记录**（日常录入的主战场）
4. 然后**付款记录**
5. **应付**与**日报**用公式自动算
6. 最后搭**看板**（引用前面所有表）

## 九、自检

- [ ] 合同编号在三张表里完全一致
- [ ] 现货到货已单独标记，不参与合同进度
- [ ] 未到量口径唯一，且求和范围避开合计行
- [ ] 应付金额含负号处理，"欠货"状态能看到
- [ ] 日报的用量是反推的，不需要手工填
- [ ] 反推公式不依赖行排序
- [ ] 看板指标用"找最新行"而非钉死行号，且用了两套锚
- [ ] 参数集中在参数表，未写死在公式里
- [ ] 顶部有自动提醒横幅
