# 02 · 申请单与询比价登记

## 一、采购申请单登记

申请单是台账的**上游来源**：先有申请，才有询价、比价、下单、到货、付款。

### 该提取的字段

| 字段 | 说明 |
|---|---|
| 审批编号 / 申请单号 | **唯一标识，必须原样保留** |
| 申请日期 | |
| 申请人 / 部门 | 后续按人统计工作量要用 |
| 物品明细 | **逐条拆行**（同发票规则，不允许合并） |
| 用途 / 备注 | |
| 期望到货日期 | 用于排期与催货 |

### 与下游对齐的关键设计

1. **申请单号作为跨表关联字段**——询价单、采购订单、到货记录、付款记录都应带上它。**编号不一致就串不起来。**
2. **申请台账要留出"状态"列**：未询价 / 询价中 / 已定标 / 已下单 / 已到货 / 已结清。这一列是把"申请→到货"整条链可视化的关键。
3. **同一申请单可能拆成多次采购**——不要把"一单一行"写死，要允许一对多。

### 处理完后

- 已处理的原件**移动到已完成目录**，避免重复处理
- 提取失败的（如扫描件识别不出编号）**单独列出**

## 二、询比价登记

### 数据结构：一张询价单，多家报价

⚠️ **不要每家建一条独立记录**，那样比不了价。正确结构是：

```
询价单（一行）
├── 询价单号 / 日期 / 物料 / 规格 / 数量 / 需求方
└── 报价明细（每个供应商一行）
    ├── 供应商 / 报价日期
    ├── 未税单价 / 税率 / 含税单价 / 金额
    ├── 账期 / 交货期 / 最小起订量
    └── 备注（是否含运、是否含税、有效期）
```

**报价行是子表**，靠询价单号归属到主单。

### 登记时要归一的口径

**这是询比价登记最容易被忽略、也最影响结论的地方**——报价看起来能比，其实口径不同：

| 差异项 | 处理 |
|---|---|
| 含税 / 未税 | 统一折算到**同一口径**（通常用含税净单价） |
| 含运 / 未运 | 运费折算进单价，或单列 |
| 税率不同 | 不能直接比含税价，要折算到同税率或比未税价 |
| 一次性费用 | 按预计数量**摊销**到单价 |
| 币种不同 | 统一到同一币种（用同一汇率日期） |
| 有效期不同 | 标注，影响最终选择 |
| 最小起订量不同 | 标注，可能导致实际单价变化 |

⚠️ **只比"含税单价"数字大小、不归一化，是最常见的选错供应商原因。**

### 定标登记

定标时要记录：

- **中标供应商**、**中标单价**、**授标量或份额**
- **落标原因**（价格 / 资质 / 交期 / 综合评分）——这一列是复盘的依据
- **定标日期与依据**（比价表 / 评分表 / 会议纪要）

⛔ **权重与评分标准应在开标前确定并留痕**，不要在看过谁价格低之后再定。

### 未匹配与异常

- 报价里出现**新的物料名称**——归不进现有类别，单独列出
- 报价里出现**新的供应商**——通讯录里没有，单独列出待补
- **同一次询价缺报价**——记录"未响应"，这也是信息（影响后续是否继续邀请）

## 三、自检

**申请单**

- [ ] 明细已逐条拆行，没有合并行
- [ ] 审批编号原样保留，且与下游表一致
- [ ] 状态列已填写
- [ ] 原件已移入已处理目录
- [ ] 提取失败的已单独列出

**询比价**

- [ ] 询价单/报价明细是主从结构，不是平铺
- [ ] 报价已归一化到同一口径（含税、含运、同币种）
- [ ] 一次性费用已摊销
- [ ] 落标原因已记录
- [ ] 未响应供应商已标注
- [ ] 新物料、新供应商已列出
