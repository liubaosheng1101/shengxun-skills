# 06 · 字幕规范与自检

字幕是**完播率的隐性杀手**——排版错了观众未必说得出哪里不对，但会划走。

## 一、先分清字幕的两种存在形态

| 形态 | 是什么 | 怎么查 |
|---|---|---|
| **字幕文件** | 独立的 `.ass` / `.srt` 文件，播放器叠加 | 解析文件即可，**零成本、可全量查** |
| **烧入画面** | 字幕已合成进视频像素 | **只能靠抽帧 + OCR**，成本高 |

⚠️ **最容易踩的认知坑**：如果字幕已经烧进画面，**用字幕文件版工具是查不到的**——文件里没有字幕，工具会报"全部通过"。**先确认字幕是哪一种形态，再选工具。**

## 二、文本与时间的来源必须分开

**这是字幕环节最重要的一条铁律。**

```
文本  ← 脚本原文（一个字不改）
时间  ← 语音（真实发声时刻）
```

⛔ **绝不拿语音转写文本当字幕。** 转写会把专业词听错——实测「报价单」被听成「暴甲单」、「供应商」被听成「公应商」，**专业人设直接砸**。转写只负责给时间。

### 字级对齐（时间轴的精度）

更好的做法是**字级对齐**：时间轴取自真实的字级发声时刻，而不是"按字数比例摊开"。

| 做法 | 时间来源 | 结果 |
|---|---|---|
| **字级对齐** | 真实字级发声时刻 | 文本取脚本、时间取音频，**字幕零错字，且屏与屏之间无空洞** |
| 按字数摊开（旧法） | 按比例线性分配 | 屏间会产生约 0.05 秒的**缝隙**，整片累计约 20 帧"无字"闪动 |

⚠️ 时间轴必须**严格递增且无空洞**。渲染时按 `起 ≤ t < 止` 定位当前屏——**一旦有空洞，那一瞬间就没有字幕，表现为"闪字"。**

## 三、排版硬指标

| 项 | 规范 | 为什么 |
|---|---|---|
| **单行** | 不叠字、不同帧多行 | 叠字难看且遮挡 |
| **每屏字数** | 约 15 个汉字/屏 | 太多念不完，太少频繁跳 |
| **背景** | **透明**（描边式，只有描边与阴影） | 有底框会遮挡画面 |
| **底部安全区** | 留出约 **12%** 屏高的安全区 | 平台 UI 会遮挡底部 |
| **屏间推进** | 随口播**逐行**推进 | 整段一次显示会让人去看屏不听 |
| **浅底反色** | 浅色画面的字幕用**深色字 + 白色描边** | 浅底上用白字会糊 |
| **字号** | 按**屏宽百分比**定，不按固定像素 | 不同分辨率下要一致 |

⚠️ **字号容易定得过大**。一个真实案例：初版字号按固定像素设在 54，占屏过宽；改成按屏宽比例（约 2.8%）后才舒服。**定字号时按屏宽算，别写死像素值。**

## 四、文本层要查的错

这些错**肉眼不易发现，但会被观众察觉**：

| 错 | 表现 | 后果 |
|---|---|---|
| **行首标点孤行** | 一行的开头是个标点 | 明显的排版瑕疵 |
| **词中折断** | `供应商` 被断成上一行 `供应` + 下一行 `商` | 读起来别扭 |
| **同屏折行断词** | 断点落在词中间 | 同上 |
| **屏尾连接词** | 一屏以"的""和""然后"结尾 | 观众以为还有下文，下一屏却跳了 |
| **闪现** | 某屏停留过短（看不清） | 信息丢失 |
| **时间重叠** | 两屏时间区间交叠 | 渲染时互相顶掉 |
| **时间间隙** | 两屏之间有空当 | 闪字（见第二节） |
| **字幕超速 / 过慢** | 单屏每秒字符数（CPS）过高的屏一闪而过，过低的屏拖住节奏 | 影响可读性；阈值按语速自行标定，同一账号内保持一致 |
| **有语音无字幕** | 有说话的段落却没有对应字幕 | 观众以为漏听了 |
| **有字幕无语音** | 无人声却有字幕 | 通常是时间轴错位 |

## 五、烧入画面版的质检方法

字幕已烧进画面时，只能抽帧再识别。**流程与判据如下**：

### 第 1 步：抽帧

用**单次**抽帧滤镜（按固定帧率抽），**不要逐帧 seek**——逐帧 seek 会慢到不可用。

### 第 2 步：裁字幕带

裁出**画面底部含屏幕底部**的横条，并适当放大——字幕带一般比常规区域需要更高的识别分辨率。

### 第 3 步：OCR 识别

用**离线 OCR**（不联网、零成本、可反复跑）。

### 第 4 步：聚类成屏

把各帧识别结果**按位置分带聚类**成"屏"。

### 第 5 步：判定哪些是字幕

⚠️ **不能把所有识别到的文字都当字幕**。画面里还有标题、水印、道具上的字。

**判为字幕的三条同时满足**：

1. **连续 ≥2 帧稳定**（字幕会停留多帧，一闪而过的是噪声）
2. **水平居中**
3. **中文占比 ≥50%**

不满足的按噪声丢掉。

### 第 6 步：跑上面的文本层检查

对聚类出的屏跑第四节的全部检查项。

### 优化：复用中间结果

抽帧与 OCR 是瓶颈。**把帧序列与 OCR 结果缓存下来复用**，调参时只重跑后处理——可以从分钟级降到秒级。

## 六、字幕自检清单

**排版**

- [ ] 单行，不同帧无多行、无双字幕
- [ ] 每屏约 15 字，未超长
- [ ] 背景透明（描边式），未遮挡画面
- [ ] 底部留出约 12% 安全区
- [ ] 浅底画面已用深色字 + 白描边
- [ ] 字号按屏宽比例定，未写死像素

**文本**

- [ ] 无行首标点孤行
- [ ] 无词中折断、同屏折行断词
- [ ] 屏尾无连接词收尾
- [ ] 无闪现（停留过短）
- [ ] 无时间重叠、无时间间隙
- [ ] 单屏 CPS 在可读区间内

**来源与对齐**

- [ ] 字幕文本**逐字等于脚本原文**（不是转写结果）
- [ ] 时间轴严格递增、**无空洞**
- [ ] 有语音处均有字幕，无字幕处无语音

**一致性**

- [ ] 跨文件字幕样式一致（同一账号/同一系列内）
- [ ] 字幕纵向位置无跳变

## 七、一个务实的建议

**别指望一次做完就全对。** 字幕问题的特点是：**单条视频里看不出来，连着看几条才发现规律**（比如同一类词总是被折断）。

所以：**每出一期跑一次自检，并把发现的问题记下来**。攒够几条，回头一次性改渲染规则，比逐条返工划算。
