# 02 · 文案骨架模板

**按时长选模板，把秒数先分好，再往里填内容。** 不先分秒数，写出来必然头重脚轻。

## 一、短版（50–60 秒 · 单点速讲）

适合：一个认知纠正、一个具体技巧。

| 段 | 秒数 | 作用 |
|---|---|---|
| 钩子 | 0–5s | 结论或冲突前置 |
| 案例 | 5–18s | 一个具体场景，让观众对上号 |
| 核心认知 | 18–30s | 一句话点破 |
| 要点 1–3 | 30–50s | 三个具体动作或判断标准 |
| 提醒 | 50–55s | 一个常见误区 |
| CTA | 55–60s | 一个明确动作 |

**字数参考**：60 秒 ÷ 4.2 字/秒 ≈ **250 字**。

## 二、标准版（80–100 秒 · 有分量的方法）

适合：一套方法、一个完整判断框架。**这是知识口播的主力时长。**

| 段 | 秒数 | 作用 |
|---|---|---|
| 钩子 | 0–5s | 数字或结论，第 0 秒出声 |
| 引子 | 5–15s | 交代"为什么会卡在这" |
| 核心认知 | 15–28s | 一句话给出全篇的框架 |
| 要点 ×3–4 | 28–80s | **每段 12–18 秒，各含一个真实案例** |
| 收尾 | 80–92s | 金句 + 清单式回顾 |
| CTA | 92–100s | 一个明确动作 |

**字数参考**：95 秒 ÷ 4.2 ≈ **400 字**。

## 三、长版（150–200 秒 · 系统方法论）

只在内容确实撑得住时用；**单条超过 100 秒要考虑拆条**（见 `03` 第五节）。

| 段 | 秒数 | 作用 |
|---|---|---|
| 钩子 | 0–5s | 同上 |
| 核心认知（总览） | 5–25s | 先给全景图，让观众知道有几块 |
| 要点 ×N | 25–160s | **每段 25–30 秒，各含真实案例** |
| 收尾 | 160–190s | 金句 + 清单 + CTA |

## 四、通用规则

1. **钩子必须落在第 0–5 秒**，且第 0 秒就开口（不要留白、不要先出 Logo）。
2. **每个要点都必须带案例。** 只有结论没有案例的段落，观众记不住。
3. **段与段之间要有推进关系**：递进（一层比一层深）、对比（正反）、或流程（先后）。不要并列堆砌几个不相关的点。
4. **秒数与字数要能对上。** 写完按 4.2 字/秒折算，对不上就调。
5. **CTA 只给一个动作。** "关注 + 点赞 + 转发 + 评论区留言"= 没有 CTA。

## 五、画面提示怎么写

在稿子里给每段标一个画面方向即可，**不必写分镜**：

```
【钩子 0–5s】
口播：……
画面：大字卡（数字放大）

【要点1 28–42s】
口播：……
画面：三行清单逐行出现
```

**知识类口播的画面原则**：画面是**字幕与关键词的强化**，不是主内容。满屏文字会让人去看屏而不是听。

⚠️ 如果画面要放中文，**不要用 AI 生图**——AI 生图里的中文基本是乱码，而知识视频满屏都是中文。用排版文字或矢量图形。

## 六、骨架自检

- [ ] 秒数已按段分配，合计等于目标时长
- [ ] 钩子在第 0–5 秒
- [ ] 每个要点都有案例
- [ ] 段与段之间有推进关系（递进 / 对比 / 流程）
- [ ] 段数与 `SCRIPT` 段数一一对应（不要多写一段没画面的）
- [ ] CTA 只有一个动作
- [ ] 字数与秒数能对上
