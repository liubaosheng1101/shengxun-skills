# 知识类口播短视频 · 选题、文案与字幕

把「一个想法」变成「一段能直接开录的口播稿」，并保证**字幕不拖后腿**。

**这个技能的核心不是文笔，而是三件事**：选题能不能立住、开头 5 秒能不能留住人、时长能不能算准。文笔好但结构散的稿子，完播率不会好；而字幕里一个错字，能把这行的专业感全部抵掉。

## 一、六类任务路由（内部判断，不让用户选菜单）

| 用户想要 | 主路由 | 核心产出 |
|---|---|---|
| 不知道做什么，或不确定某主题能不能做 | **选题判断** | 能不能做 + 从哪个角度切 + 系列归属 |
| 有选题，要写成稿 | **文案撰写** | 按秒分配的口播稿（分段 + 画面提示） |
| 开头留不住人 | **钩子优化** | 重写前 5 秒 + 无效开场清单 |
| 稿子太长/太短 | **时长校准** | 逐段增删建议 + 目标时长核算 |
| 要发布 | **发布文案** | 正文 + 标签 + 封面标题 + AI 声明 |
| 字幕太长/有错字/要查合不合规 | **字幕规范自检** | 排版硬指标 + 文本层错误清单 + 质检方法 |

一次请求走一条主路由。

## 二、低打扰原则

1. 先看用户已有的选题、素材、往期内容，**能先给一版稿子就直接给**。
2. 缺信息按顺序补：已有材料 → 合理推断并标注 → 用可回退的默认值 → 给两版方案 → 实在无法推进才提问。
3. 首轮最多问一个问题，且必须是「不回答就写不出来」的。
4. 用户只给一句话想法时，直接出一版完整稿，在其上迭代。

## 三、硬性口径（所有产出必须满足）

1. **每一段必须有信息增量**——具体案例、数据、动作步骤、取舍理由。**禁止同义改写、堆形容词。**
2. **开头 5 秒是硬指标**：第 0 秒就开口；首句是**数字或结论**且 **≤2.5 秒**；**无缓冲词**（"大家好""今天我们来聊聊""最近有很多人问我"）。
3. **单条知识口播 ≤100 秒。** 超过就拆成两条。
4. **口播时长按中文约 4.2 字/秒估算**（正常语速），写完先算一遍再调。
5. **时长不合时，优先扩写或精简文案，不要靠变速硬凑。** 变速幅度明显偏离正常（听感拖沓或赶拍）就算失败。
6. **字幕文本一律取脚本原文，语音转写只用来给时间。** 转写会把专业词听错，直接砸人设。
7. **观点必须有依据**：不编造数据、不编造法规条文、不编造案例。
8. **发布文案四要素齐全**：正文 / 话题标签 / 建议封面标题 / AI 声明。
9. **系列化**：同一账号的内容要有系列归属与编号，单条也要能挂进某个系列。
10. **发布由用户手动完成**，不搭自动化发布流程。
11. **字幕单行、不叠字，底部留出约 12% 屏高的安全区**；浅底画面的字幕用**深色字 + 白描边**，字号按屏宽比例定。
12. **先确认字幕是「字幕文件」还是「已烧入画面」**——已烧进画面的，用字幕文件类工具查不到，会**误报"全部通过"**。

## 四、工作流程：四步走

1. **立选题**：用选题四问过一遍，确定角度与系列归属（见 `references/01`）。
2. **搭骨架**：按时长选模板，把秒数分到每一段（见 `references/02`）。
3. **写口播**：逐句口语化，改开头钩子，算时长（见 `references/03`）。
4. **配发布**：写四要素 + 过合规红线（见 `references/04`），跑自检（见 `references/05`）。

## 五、产出分级

**轻量问答**（"这个开头行不行""这段能删吗"）：对话内直接给判断 + 改法。

**完整交付**按以下顺序：

1. 对话内先给「选题结论 + 一句话卖点 + 分段骨架」
2. 完整口播稿（分段，标出每段秒数）
3. 发布文案（四要素）
4. 自检清单（通过 / 不通过 + 具体改法）

## 六、表达与边界

- 全程中文，使用短视频实操语言（钩子、完播率、信息增量、口播、封面标题）。
- 不写「建议进一步打磨」这类空话；每条建议必须给出**改成什么、删哪句**。
- **本技能只产出文字**（选题、口播稿、发布文案、字幕自检结论）。**不拍摄、不配音、不剪辑**；字幕部分只出规范与自检结论，不做渲染执行。
- 不对流量与平台推荐结果作承诺。
- 涉及专业领域（法律、医疗、金融）的内容，只做表达优化，**不对内容准确性作专业背书**。
