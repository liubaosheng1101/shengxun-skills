# 06 · 质量校验与验收

**这一步不能省。** 合并出来的表看起来没问题，但金额对不上往往就藏在这里。

## 一、七项数据质量校验

每一项都写进「数据备注」列，用户可直接筛选。

| 校验项 | 判定条件 | 说明 |
|---|---|---|
| 日期超出台账年度 | `日期.year` 不在应有年份内 | 明显的登记错误 |
| 未填物料类别 | 标准化后为空 | 影响分类汇总 |
| **含 Excel 错误值** | 关键列值以 `#VALUE! / #N/A / #REF! / #DIV/0! / #NAME? / #NULL! / #NUM!` 开头 | 见下文传播问题 |
| 金额缺失 / 为 0 / 为负 | — | 需业务确认，不一定是错 |
| **数量 × 单价 ≠ 金额** | `abs(数量*单价 - 金额) > 0.05` | 金额一般以发票为准，**错的多是数量或单价** |
| **疑似重复登记** | 同 `日期 + 物料名称 + 金额 + 供应商` 出现 >1 次 | 见下 |
| 供应商名称待规范 | 命中名称归一候选组 | 见 `04` |

## 二、疑似重复：只标注，不自动去重

⛔ **不要自动去重。**

同日期、同物料、同金额完全可能是**真实的多笔**（分次到货、多车次、重复采购同一耗材）。

**正确做法**：

1. 只**标注**（在「数据备注」列写「疑似重复」）
2. 单独出一份清单
3. 由业务判断

**理由**：误删真实数据，比留着重复严重得多——前者是数据损坏，后者只是看起来不干净。

## 三、`#VALUE!` 会向外传播

若某行供应商名就是 `#VALUE!`（源表公式报错后被粘贴成值），**任何引用它的单元格都会变成错误值**，连锁污染整个汇总和看板。

**处置**：

- **明细表保留原值**（不改动源数据）
- **汇总 / 看板里替换成可读占位符**，如 `⚠️ 源表错误值，名称待补`
- 并把该行计入质量问题清单

## 四、验收：必须读计算值

⚠️ **`openpyxl` 不计算公式**。用 openpyxl 读一个公式单元格，拿到的是公式字符串，不是结果。**拿它做验收等于没验。**

**在 Windows 上必须用 `win32com` 打开 Excel 读计算值**（非 Windows 环境的降级口径见 SKILL.md「六、表达与边界 · 运行环境」）：

```python
import win32com.client as w32

xl = w32.gencache.EnsureDispatch("Excel.Application")
xl.Visible = False
wb = xl.Workbooks.Open(ABS_PATH)

ws = wb.Worksheets("采购明细")
print(ws.ListObjects(1).Name, ws.ListObjects(1).Range.Address)

# 读关键单元格的计算值
print(xl.WorksheetFunction.Sum(ws.Range("N2:N10000")))
print(wb.Worksheets("分析看板").Cells(6, 2).Text)

wb.Close(False)
xl.Quit()
```

## 五、必须核对通过的项

1. **明细行数 == 各源表数据行数之和（零丢弃）**
   ⚠️ 这是最重要的一条。有丢弃说明解析环节漏了行（最常见是日期没解析出来）。
2. **各年度金额 == 原台账口径**（逐个年度对）
3. **月度趋势各月合计 == 源月度表合计**（**逐月对账**）
4. **看板所有指标有值**，无 `#VALUE!` / `#REF!`
5. **图表数量与标题正确**

### 逐月对账（抓漏行最有效）

读各月工作表的「总计」行，与合并后按 `年度+月份` 聚合的结果**逐月对比**。差异月份要**逐条查**——多数是那一个月有新的日期格式没被解析。

## 六、源表之间本身不一致怎么办

⚠️ **年度汇总表与月度表可能本身就对不上**（历史登记差异）。

**处置原则**：

1. **以数据行完整的表为准**（通常是逐月登记的月度表，或标记为年度汇总的那张）。
2. **差异如实告知用户**：列出差异月份与金额。
3. ⛔ **绝不擅自"调平"**。调平会掩盖真实的登记问题，让问题永远查不出来。
