# 03 · 分类体系归一

**「台账乱」的主要来源，往往不是数据本身错，而是分类体系换过。**

## 一、问题形态

同一批采购记录，因为不同年度/不同登记人用了不同分类口径，会分裂成几十种写法：

- **多级制**：`大类(子类)` 形式，如 `五金工具(管件)`、`辅材(劳保)`
- **扁平制**：直接写大类名
- **同义异名**：`办公用品及服务` / `办公后勤及服务类采购` / `办公用品及服务类采购`
- **错别字与全半角混用**：`辅材` 写成 `辅村`；全角括号「（）」与半角括号「()」混用
- **残留符号**：`辅材*`（通配符残留）

**后果**：做分类汇总时，同一类被拆成 3–4 行，看板失真。

## 二、统一策略：三级并存，可追溯

不要直接覆盖原值。**同时保留三列**：

| 列 | 内容 | 作用 |
|---|---|---|
| 原始类别 | 源表原值，**原样不动** | 可追溯、出问题能回查 |
| 物料类别 | 标准化后的**二级**分类 | 保留业务颗粒度 |
| 物料大类 | 统一后的**一级**分类 | 用于看板与汇总 |

这样即使映射规则有误，也能回退重算，而不是把原始信息毁掉。

## 三、一级大类怎么定

**不要照搬任何现成清单**——一级大类的划分取决于该单位的物料结构。做法：

1. 先把所有原始类别去重打印出来（可能几十到上百种）
2. 按业务含义**人工归并**成 8–12 个大类（太少失去区分度，太多等于没归并）
3. 留一个 **「其他」兜底**
4. 归并规则写成显式映射表，**不要靠模糊匹配**（模糊匹配容易把不同物料并到一起）

映射表长这样（示意，具体按实际填写）：

```python
CATEGORY_MAP = {
    "统一大类A": ["原始写法1", "原始写法2", "原始写法3"],
    "统一大类B": ["原始写法4", "原始写法5"],
    # …
    "其他": [],          # 兜底
}
```

## 四、清洗顺序（顺序很重要）

```python
s = raw.strip()
s = s.replace("（", "(").replace("）", ")")   # 1. 全角括号 → 半角
s = s.replace("常见错别字", "正确写法")         # 2. 高频错别字修正
s = s.replace("*", "").strip()                # 3. 通配符残留
s = re.sub(r"\s+", "", s)                     # 4. 去掉所有空白（含换行）
```

⚠️ **顺序不能颠倒**：

- 先做全角转半角，后面的括号匹配才可靠。
- 先去空白，否则「辅 材」这种中间带空格的写法匹配不上——名称里嵌换行符、空格是很常见的。

## 五、必须有的兜底：UNKNOWN 计数器

```python
UNKNOWN = collections.Counter()
# 映射时
mapped = map_category(s)
if mapped is None:
    UNKNOWN[s] += 1
    mapped = ("其他", "其他")
# 收尾
print("未映射类别：", UNKNOWN.most_common())
```

**判据：`UNKNOWN` 为空（或已逐条确认确实该归「其他」）才算清洗干净。**

只看总数对得上是不够的——未映射的类别会被静默归入「其他」，把「其他」这个桶撑大而不自知。

## 六、自检清单

- [ ] 原始类别列**原样保留**，未被覆盖
- [ ] 一级大类数量在 8–12 个（含「其他」）
- [ ] 映射表是**显式枚举**，不是模糊匹配
- [ ] 清洗顺序：全角→半角 → 错别字 → 通配符 → 去空白
- [ ] `UNKNOWN` 计数为 0，或未映射项已逐条确认
- [ ] 「其他」大类的占比合理（占比过高说明归并规则没覆盖完整）
