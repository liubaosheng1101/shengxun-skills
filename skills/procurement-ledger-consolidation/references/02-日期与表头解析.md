# 02 · 日期与表头解析

这是台账清洗里**最容易静默出错**的一环。错了不报错，只是金额对不上。

## 一、日期列有三种形态

同一列里可能混用：

| 形态 | 例子 |
|---|---|
| `datetime` / `date` 对象 | 库直接读出来就是日期 |
| 字符串 | `'2026-07-23'`、`'2026/7/23'`、`'2026年7月23日'` |
| **Excel 序列号（整数）** | `45664` —— **最容易被漏掉的一种** |

⚠️ **如果只判 `isinstance(v, datetime.date)` 就跳过，会静默丢失上百行**。而且丢行后金额对不上时，极难定位原因。

## 二、统一解析函数

```python
import datetime, re

def to_date(v):
    if isinstance(v, datetime.datetime):
        return v.date()
    if isinstance(v, datetime.date):
        return v
    if isinstance(v, bool):                       # 注意：bool 是 int 的子类，必须先拦掉
        return None
    if isinstance(v, (int, float)):               # ← Excel 序列号
        n = float(v)
        if 20000 < n < 60000:                     # 合理区间，排除误当日期的小数字
            return datetime.date(1899, 12, 30) + datetime.timedelta(days=int(n))
        return None
    if isinstance(v, str):
        s = v.strip()
        if s in ("", "-", "/"):
            return None
        for fmt in ("%Y-%m-%d %H:%M:%S", "%Y-%m-%d", "%Y/%m/%d", "%Y.%m.%d",
                    "%Y年%m月%d日", "%Y-%m-%d %H:%M", "%Y/%m/%d %H:%M:%S"):
            try:
                return datetime.datetime.strptime(s, fmt).date()
            except ValueError:
                continue
        try:
            n = float(s)
            if 20000 < n < 60000:
                return datetime.date(1899, 12, 30) + datetime.timedelta(days=int(n))
        except ValueError:
            pass
        # 脏日期兜底：年月份粘连 '20256/6/16'、多重分隔符 '2025//8/23'
        m = re.match(r"^\D*(\d{4})\d{0,2}[/\-.]{1,2}(\d{1,2})[/\-.]{1,2}(\d{1,2})\D*$", s)
        if m:
            try:
                return datetime.date(int(m.group(1)), int(m.group(2)), int(m.group(3)))
            except ValueError:
                return None
    return None
```

**要点**：

- Excel 序列号的基准日是 **1899-12-30**（不是 1900-01-01），这是 Excel 的历史闰年 bug 导致的偏移，用错会整体差 2 天。
- `bool` 必须先拦——`True` 是 `int` 的子类，不拦会被当成序列号 1。
- 合理区间 `20000 < n < 60000` 对应约 1954–2064 年，用来排除把数量、金额误当日期的情况。

## 三、抽完必须自检

```python
bad = [(i, raw) for i, raw in rows if to_date(raw) is None and str(raw).strip() not in ("", "-", "/")]
assert not bad, f"未能解析日期的行：{bad[:20]}"
```

**判据：`未能解析日期的行数 == 0`**，并把解析失败的**原始值逐条打印出来看**——它们往往指向新的脏数据格式，把格式补进解析函数即可。

## 四、表头名映射：绝不硬编码列号

**各表列序不同，硬编码列号必然错配。**

实测常见差异：同一含义的列，有的表在第 8 列、有的在第 10 列；同一张表不同年份的列序也会调整。

做法：建**别名表**，把表头名映射到标准字段名。

```python
ALIAS = {
    "序号": "序号", "序列": "序号",
    "日期": "日期",
    "物料类别": "物料类别", "物资类别": "物料类别",
    "单价": "含税单价", "含税单价（元）": "含税单价", "含税单价": "含税单价",
    "未税单价（元）": "未税单价", "未税单价": "未税单价",
    "金额": "金额", "金额（元）": "金额",
    "税率（%）": "税率", "税率": "税率",
    "供应商名称": "供应商名称", "供货商": "供应商名称", "供应商": "供应商名称",
    # …
}

# ⚠️ 表头必须 .strip()——原表里常见前导空格
key = ALIAS.get(str(ws.cell(header_row, c).value).strip())
```

**别名表要逐步补齐**：每遇到一个映射不上的表头，就打印出来（见下），补进 `ALIAS`。

```python
if key is None and ws.cell(header_row, c).value is not None:
    unmapped.add(str(ws.cell(header_row, c).value).strip())
```

## 五、表头行位置不一

**表头可能在第 1 行、第 2 行，也可能在第 17 行**（前面有标题、说明、合并单元格）。

做法：不要假设。按文件类型配置 `header_row`，或写一个自动探测（找那一行里命中 `ALIAS` 关键字最多的行）。

## 六、跳过规则

合并时必须跳过的行：

- **汇总行 / 合计行**（序号列或首列写着「汇总」「合计」「小计」）
- **日期与金额同时为空**的行
- 表尾的空行（`max_row` 常因历史错误数据虚高，先清理）

⚠️ **不要用「金额为空就跳过」作为唯一规则**——有真实记录金额暂时未填，跳过会丢数据。

## 七、自检清单

- [ ] 未解析日期的行数 == 0（或已逐条确认原因）
- [ ] 未映射的表头已收集并处理，计数为 0
- [ ] 每个文件的表头行号已确认（不是假设）
- [ ] 汇总行 / 合计行已跳过
- [ ] 表头 `.strip()` 已加（前导空格）
- [ ] 数据行数与源表可见数据行数一致
