# 04 · 供应商名称归一

**这是台账分析里"价值最高、也最容易被忽略"的一步。**

## 一、问题形态

同一家供应商在台账里可能有多种写法，导致**它的采购额被拆散到多个名下**，排名和占比全部失真。

常见成因：

- **后缀不同**：有的写全「XX有限公司」，有的只写「XX」
- **简称 / 全称混用**
- **名称内嵌换行符或空格**（复制粘贴留下）
- **错别字**：形近字替换、后缀缺字（`有限` / `有限公`）
- **全半角括号不一致**
- **带括号备注**：`XX（原XX）`、`XX(分公司)`

**后果**：某家实际是第一大供应商，却在报表里分列第 1、6、7、12 名。

## 二、归组算法：去后缀核心名 + 包含关系 + 相似度

三步并查集。

### 第一步：取核心名（去掉企业后缀与括号备注）

```python
import re, difflib

SUFFIXES = ("股份有限公司", "有限责任公司", "有限公司", "公司",
            "经营部", "经销部", "销售处", "门市部", "旗舰店", "商店",
            "超市", "批发部", "店", "厂", "中心", "处", "部")

def core(s):
    s = re.sub(r"\s+", "", str(s))          # 关键：名称里可能嵌换行符/空格
    s = re.sub(r"[（(].*?[)）]", "", s)      # 去掉括号备注
    for suf in SUFFIXES:                    # 从长到短匹配，避免「有限公司」被「公司」先截
        if s.endswith(suf) and len(s) > len(suf):
            return s[:-len(suf)]
    return s
```

⚠️ **后缀列表必须从长到短排列**——否则 `XX有限公司` 会先被 `公司` 截成 `XX有限`。

### 第二步：并查集归组

```python
CORES = {n: core(n) for n in names}
parent = {n: n for n in names}

def find(x):
    while parent[x] != x:
        parent[x] = parent[parent[x]]
        x = parent[x]
    return x

def union(a, b):
    ra, rb = find(a), find(b)
    if ra != rb:
        parent[rb] = ra

for i in range(len(names)):
    for j in range(i + 1, len(names)):
        a, b = names[i], names[j]
        ca, cb = CORES[a], CORES[b]
        # 判据一：核心名完全相同，或一者包含另一者
        same = (ca == cb) or (len(ca) >= 3 and len(cb) >= 3 and (ca in cb or cb in ca))
        # 判据二：长度接近时看相似度
        if not same and abs(len(ca) - len(cb)) <= 3:
            same = difflib.SequenceMatcher(None, ca, cb).ratio() >= 0.88
        if same:
            union(a, b)
```

### 第三步：按组输出

每组给出：组号 / 组内合计金额 / 各写法 / 各自笔数与金额 / **建议规范名（取组内金额最大者）**。

## 三、阈值怎么标定（关键）

相似度阈值取 **0.88** 是实测标定的结果。**它必须同时满足两个方向**：

| 方向 | 例子 | 相似度 | 期望 |
|---|---|---|---|
| 应合并 | 同一家，其中一方有**形近错别字** | ≈ 0.93 | ✅ 合并 |
| 应合并 | 同一家，其中一方**内嵌换行符 / 后缀不全** | ≈ 0.97 | ✅ 合并 |
| **不应合并** | 两家**高度相似但确实是不同**的公司（名称仅一两字之差、同地区同行业） | ≈ 0.83 | ❌ 不合并 |

**阈值定得太低（如 0.80）会把真实的两家不同公司并成一家**——这是比漏合并严重得多的错误。**宁可漏合并，不可误合并。**

**务必用你自己的数据做一次标定**：挑几对"确定是同一家"和几对"确定是两家"的名称，看它们的相似度分布，把阈值放在两簇之间。

## 四、绝对不要自动合并

**只输出清单，等业务确认后再批量替换。**

原因：

- 相似度算法无法理解业务关系（母子公司、更名、代持）——这些**不该合并**，但算法会合并。
- 误合并会直接改变金额归属，属于**不可逆的数据破坏**（原始名称一旦被批量替换，很难还原）。

**正确流程**：

```
算法出候选组清单 → 人工逐组确认（合并 / 不合并 / 待查）
→ 确认后再批量替换 → 保留「原始供应商名称」列以备回退
```

## 五、常见错别字模式（建你的自查表）

清洗时优先扫描这几类：

| 模式 | 说明 |
|---|---|
| **形近字替换** | 地名、公司名里的形近字（笔画相近、易看错或易打错的字） |
| **后缀缺字** | `有限`、`有限公`（少了「司」） |
| **同音字** | 「有现」→「有限」 |
| **名称内嵌空白** | 换行符、多余空格 |
| **全半角括号** | 「（）」与「()」 |
| **通配符残留** | 名称尾部的 `*` |

⚠️ 名称里的**空白字符**是最隐蔽的一类——在 Excel 里看不出来，但会导致字符串比较失败。**所有名称比较前必须先 `re.sub(r"\s+", "", s)`。**
