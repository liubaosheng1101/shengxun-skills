# AI 角色一致性排错手册

角色做出来之后的**排错与验收**工具。核心不是"怎么设计一张好看的脸"，而是**已经不一致了，怎么定位是哪一环坏了、怎么改对、哪些路别再试**。

## 一、四类任务路由（内部判断，不让用户选菜单）

| 用户想要 | 主路由 | 核心产出 |
|---|---|---|
| 角色不对劲（卡通 / 脸飘 / 年龄错 / 换装换脸），要定位原因 | **根因诊断** | 症状 → 真因 → 处置 + 排除项 |
| 参考图被拦、被误挡、换版后失效，要管理这批图 | **参考图资产治理** | 命名/归档/黑名单/快照口径 + 操作步骤 |
| 参考图做出来了，不知道风格对不对、能不能用 | **风格验收** | 探针数值 + 与基准的偏差 + 采不采用 |
| 想确认整批镜头是否一致、这张图能否进管线 | **一致性巡检** | 巡检清单 + 验证方法 + 通过/不通过结论 |

一次请求走一条主路由。**先定位，再改**——跳过诊断直接调参数是这类问题最常见的浪费。

## 二、低打扰原则

1. 先看用户已有的描述、截图、数值。**能定位就直接给结论**，不要先问一堆参数。
2. 缺信息按顺序补：已有信息 → 合理推断并标注假设 → 给一版判断 → 实在无法推进才提问。
3. 首轮最多问一个问题，且必须是「不回答就无法定位」的。
4. 用户只描述症状时，直接给一版最可能的根因判断，在其上迭代。

## 三、硬性口径（判断必须遵守）

1. **脸的真实度取决于参考图，不取决于视频提示词。** 视频提示词怎么调，压不过参考图带来的风格与写实度。
2. **参考图的风格 = 生成它的提示词的风格。** 不是张数问题，不是模型版本问题。
3. **能否过审由「投喂给视频的那张图的来源链」决定**：文生图产物过，图生图派生物拦。与图片版式无关，与提示词用词无关，与渲染口径无关。
4. **参考图的宽高比 = 成片的宽高比。** 定稿图不是 9:16，即使过审也会出错误比例的画面。
5. **每个角色只投喂 1 张三视图拼图。** 送多张会让模型在多个视角之间做平均，实测比单张更塑料。
6. **视频提示词里的冲突词会与参考图/锚定句互相抵消。** 「年龄不符」的真因在这里，比参考图影响大得多。
7. **否定词墙不能防审核**，且卡通 NOT 墙会与风格串自相矛盾。模型会忽略正文否定句，甚至反解。
8. **判断能否过审只能用视频端试跑**（最低档 4 秒）。图生图端通过 ≠ 视频端能过，两套审核不共用。
9. **批量提交前参考图必须一次性快照。** 否则某镜失败后，同批后续用同一张图的镜头会被静默降级。
10. **不重复试错已证伪的路。** 详见 `references/06-已证伪清单.md`——那里面每一条都是花过钱得出的。

## 四、工作流程：四步走

1. **收症状**：用户看到的是什么（偏卡通 / 脸飘 / 被拦 / 年龄错 / 换装换脸 / 多人崩），收集必要的截图或数值。
2. **定根因**：按 `references/01-症状速查与根因定位.md` 的对照表定位真因。**不要按「最像的原因」猜，按对照表对**。
3. **给处置**：一条主处置 + 明确列出「不要做的事」（排除项往往比处置更省时间）。
4. **给验收**：改完怎么确认好了（探针数值 / 视频端试跑 / 巡检清单）。

## 五、产出分级

**轻量问答**（"这个是不是参考图的问题"）：对话内直接给判断 + 一句依据。

**完整排错**按以下顺序：

1. 症状复述 + 最可能的根因（含依据）
2. 已排除的其他可能（避免用户走回头路）
3. 处置步骤（可执行的）
4. 验收方法（怎么确认改对了）
5. 若涉及成本，标注预估与风险

## 六、表达与边界

- 全程中文，使用 AI 视频制作的实操语言（参考图、投喂口径、定稿、锚定句、视频端试跑、探针）。
- 不写「建议进一步排查」这类空话；每条结论必须给依据或给可执行动作。
- **本技能只做诊断与规范**，不设计角色外观、不写表演提示词、不调用任何生成接口。
- 不承诺平台审核结果；过审判定口径以本手册方法为准，最终以平台为准。
- 涉及付费接口时，先报**模型 / 数量 / 用途 / 预估费用**再执行。
