# 01 · 决策路由与 TRACE 流程

本文件处理三个问题：用户的请求属于哪类采购决策、分析按什么顺序推进、什么条件下结论不能给。

## 一、决策对象（每次分析必须锁定至少一个）

- 供应商短名单：谁值得进入尽调或询价
- RFx 设计：问什么、报价怎么归一、按什么标准评
- 授标与份额分配：谁中标、分多少、附带什么条件
- 价格/时机判断：这个价能不能接受、现在买还是等等
- 谈判姿态：目标价、底线、手里有什么筹码
- 供应商处置：扶持、减量、暂停导入还是淘汰退出
- 补货决策：订不订、订多少、什么时候到
- 库存处置：加急、调拨、退货还是清呆滞
- 线路/贸易术语选择：哪种履约方案可行且划算
- 审批结论：批准、有条件批准、先试点、暂缓、否决

如果一段话只描述了现状、没有改变任何决策，要补上"所以建议怎么做"，或明确标注为"仅监控"。

## 二、按决策路由，不按职位路由

| 典型信号词 | 主路由 | 常见辅助路由 |
|---|---|---|
| 比价、几家报价、选哪家、短名单、招标、授标 | 寻源授标 | 价格、绩效风险 |
| 涨价、降价、历史价、均价、行情、现在能不能买、谈价 | 价格分析 | 寻源、物流 |
| 合格率、延期、质量、索赔、产能、审厂、风险 | 绩效风险 | 寻源、库存 |
| 断货、安全库存、再订货点、呆滞、周转、备货 | 库存补货 | 绩效（提前期可靠性） |
| 海运费、关税、到岸价、清关、船期、贸易术语 | 物流税费 | 寻源 |

注意：采购经理问海运费对比，走物流路由；计划员评估供应商交期可靠性，以绩效路由为主、库存为辅。

## 三、TRACE 五阶段

### T — Target 定决策

用一句话锁定：批准什么动作、规格/等级/SLA 是什么、数量与周期口径、预算与硬约束、与什么基线比较、谁在什么时限内按什么规则批。

不合格的目标："找一家最好的连接器供应商。"
合格的目标："在年需求 12 万只、到厂价不高于 0.95 元/只（13% 专票、人民币）、ISO9001 为强制门槛、60 天内需要首批 2 万只的条件下，选 1–2 家进入 90 天试点。"

### R — Reconcile 对齐口径

比较前建立归一化台账：

- 供应商法律主体（合同章名称）与交易名称是否为同一家；
- 物料规格、等级、品牌替代关系是否等效；
- 单位与包装（个/箱/托盘/千只）、数量阶梯与 MOQ；
- 币种、汇率来源与日期；
- 含税/未税、税率、发票类型（专票/普票）、是否可抵扣；
- 贸易术语与费用边界（运费、保险、关税、港杂谁承担）；
- 交货地、报价有效期、付款条件；
- 缺失值、争议值、暂定价、被剔除行。

计算口径覆盖率（已齐可比字段 / 全部必填比较字段），覆盖率只用于说明可信度，不得折算成供应商得分。

### A — Analyze 算经济账

分层呈现，不要只甩一个总价：

1. 报价口径价（供应商纸面价格）
2. 归一化净单价（同币种、同税率、同单位）
3. 到厂/可用单位成本（加运费、包装、入库前费用）
4. 全生命周期/年度总获取成本（加摊销、服务、切换、质量损失，减返利）
5. 预算与现金流影响（账期、一次性投入发生时点）
6. 不确定区间（汇率、运费、税率、需求量、良率波动）

差异由多个费用项构成时用瀑布式拆解；结果随需求量/汇率/运费变化时给情景矩阵。解释最大的两三个驱动项即可。

### C — Challenge 压力测试

五个透镜各过一遍：

| 透镜 | 看什么证据 |
|---|---|
| 合规 | 强制认证、环保、制裁与出口管制、海关与税务、数据与行业准入 |
| 交付 | OTD/OTIF、提前期分布与波动、排产可信度、在手订单积压 |
| 产能 | 瓶颈工序实际产出、已承诺产能、峰值承接与恢复能力 |
| 连续性 | 厂址与地域集中度、二级供应商、财务状况、单一来源依赖、灾备 |
| 符合性 | 批次合格率、PPM、来料检验、客诉、变更管理 |

每一条问题必须归入四类之一：

- **门槛项**：不通过直接淘汰/不予授标，高分不能抵
- **先决条件**：补证据或整改完成后才可批准
- **加权偏好**：可以与其他条件权衡
- **持续监控**：当前不致命，但要设触发器

重大决策至少压一个"最可能真实发生"的不利情景（如主力供应商交期拉长 50%、汇率波动 4%、需求量比预测低 20%），不要罗列通用风险清单。

### E — Execute 给带闸门的行动

每条建议必须回答：

| 要素 | 说明 |
|---|---|
| 动作 | 授标/谈判/下单/加急/试点/暂缓/退出/份额分配 |
| 责任人角色 | 采购经理/SQE/计划/财务/关务，不虚构具体人名 |
| 时机 | 日期或触发窗口（如"报价 10 月 20 日到期前"） |
| 闸门 | 动作前必须到位的证据或阈值 |
| 兜底 | 闸门不通过时的备选 |
| 复核 | 用什么指标、什么日期再看一次 |
| 停止条件 | 发生什么就暂停、反转或上报 |

禁止以"A 综合得分第一"结尾。必须说清：给 A 什么份额或金额、什么条件下给、什么情况会改变结论。

## 四、闸门评估顺序（前一关不过，后一关不补救）

1. 可行性：规格、地域、产能、提前期、法律合规
2. 证据充分性：可比字段、来源可信度、矛盾是否解决
3. 经济性：各情景下的归一化成本与总成本
4. 韧性：失效暴露面与恢复选项
5. 组合适配：集中度、双来源、可切换性、切换成本
6. 执行准备：责任人、合同条款、验收、物流、审批链路

## 五、跨模块决策链

- **授标**：强制门槛 → 归一化总成本 → 能力/绩效评分 → 不利情景压测 → 份额设计 → 合同与试点闸门
- **价格合理性**：规格口径匹配 → 内部采购历史价 → 外部行情/驱动因素 → 与供应商报价的差异桥 → 可解释区间 → 谈判或采购时机
- **补货**：可用库存+在途 → 需求分布 → 提前期分布 → 策略约束（MOQ/包装/保质期）→ 缺货与过剩情景 → 异常处置
- **进口履约**：贸易可行性 → 报价归一 → 集装箱与线路设计 → landed cost → 时效与尾部风险 → 线路组合与单证闸门

## 六、交付前自检清单

- [ ] 结论改变或控制了一个有名字的决策
- [ ] 每个被比较的价格都声明了商业口径（币种、税、贸易术语、地点、阶梯、有效期）
- [ ] 每个评分都公开了权重、方向、门槛与缺失值处理
- [ ] 每个风险都有责任人角色或决策后果
- [ ] 每个外部事实有日期和适用辖区
- [ ] "什么都不做/维持现供"的基线可见
- [ ] 最大的不确定性有验证方式、敏感性或闸门
- [ ] 合计数与原始数据范围对得上，剔除行已披露
